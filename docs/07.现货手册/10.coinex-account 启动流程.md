# coinex-account 启动流程

<div class="doc-lead">账务服务维护可用 / 冻结余额与流水，是下单占用和成交结算的记账权威之一。</div>

工程目录：`coinex-account`。可运行应用：

| 模块 | 主类 | 说明 |
| --- | --- | --- |
| `account-provider` | `AccountApp` | 核心账务 Dubbo Provider |
| `account-batch` | `AccountBatchApplication` | 批处理 / 定时任务 |

两者均为非 Web（`WebApplicationType.NONE`）+ Dubbo。

## 职责边界

| 项 | 说明 |
| --- | --- |
| 核心能力 | 冻结、解冻、扣款、入账、流水 |
| 与委托关系 | 下单占用、撤单释放、成交结算时被调用 |
| 与钱包关系 | 充提入账最终落在内部账户；链上细节见钱包手册 |

现货贯穿示例中的「占用 600 USDT / 成交扣减冻结 / 撤单解冻」都依赖本服务正确运行。

## 前置依赖

| 依赖 | 说明 |
| --- | --- |
| Apollo | provider 命名空间含 base、dubbo、redis、es 等；batch 略有差异 |
| Dubbo | compose 默认端口 provider **20880**、batch **20881** |
| MySQL / Redis / ES / RocketMQ | 由 Apollo 注入 |

在交易链路中，**account-provider 通常应早于 entrust / match 启动**（与[服务启动与验证](/pages/0203)的层次一致）。

## 启动步骤

<Flow :steps='["Apollo 与数据库就绪","mvn package","启动 account-provider","按需启动 account-batch","确认 Dubbo 注册"]' />

### 1. 构建

```bash
cd coinex-account
mvn clean package -DskipTests
```

### 2. 启动账务核心

```bash
java -Dapollo.meta=<Apollo地址> -Denv=DEV \
  -jar account-provider/target/account-provider.jar
```

或 `account-provider/src/bin/start.sh`。

### 3. 启动批处理（按环境需要）

```bash
java -Dapollo.meta=<Apollo地址> -Denv=DEV \
  -jar account-batch/target/account-batch.jar
```

batch 在启动后通过 `ApplicationRunner` 拉起多组定时任务，用于对账或批量处理类工作（具体任务以代码与 Apollo 为准）。

### 4. Docker

```bash
cd coinex-account/docker
# 按 .env / compose 配置 Apollo
docker compose up -d --build
```

默认拉起 `account-provider` 与 `account-batch`。

## 启动后检查

| 检查项 | 通过标准 |
| --- | --- |
| 进程 | provider 初始化完成，无配置或数据源错误 |
| 注册 | 交易侧可调用账务接口 |
| 业务 | 测试账户可查询余额；下单后可见冻结变化与流水 |

名词释义见[公用基础](/pages/0401)与[钱包账务](/pages/0405)；资金动作语义见[核心交易流程](/pages/0705)。
