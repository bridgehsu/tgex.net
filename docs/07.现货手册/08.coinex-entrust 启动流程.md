# coinex-entrust 启动流程

<div class="doc-lead">委托服务受理下单与撤单意图，并通过 Dubbo 对外提供能力。</div>

工程目录：`coinex-entrust`。可运行模块为 `entrust-provider`；`entrust-api` 仅提供接口定义。

## 职责边界

| 项 | 说明 |
| --- | --- |
| 业务职责 | 委托创建、状态维护、与账务占用及撮合链路协作 |
| 运行形态 | Spring Boot 非 Web（`WebApplicationType.NONE`）+ Dubbo Provider |
| 主类 | `com.exch.entrust.EntrustApp` |

下单后的资金占用由账务服务完成，撮合由 match 完成；本服务不替代二者。

## 前置依赖

| 依赖 | 用途 |
| --- | --- |
| Apollo | 配置中心；本地仅保留 bootstrap 入口 |
| Dubbo 注册中心 | 服务注册与发现（具体地址在 Apollo） |
| MySQL / Redis / ES / RocketMQ | 由 Apollo 命名空间注入，不在仓库写死 |

本地 `application.properties` 常见 namespace：`application`、`dev1.base-config`、`exbase-redis-config`、`exbase-dubbo-config`、`exbase-es-config`。AppId 见 `META-INF/app.properties`。

建议在 **account 等基础 Provider 与 Apollo 可用之后** 再启动本服务。

## 启动步骤

<Flow :steps='["准备 Apollo 与基础设施","mvn package","配置 apollo.meta / env","启动 entrust-provider","确认 Dubbo 注册"]' />

### 1. 构建

```bash
cd coinex-entrust
mvn clean package -DskipTests
```

产物：`entrust-provider/target/entrust-provider.jar`。

### 2. 本地或脚本启动

```bash
java -Dapollo.meta=<Apollo地址> -Denv=DEV -jar entrust-provider/target/entrust-provider.jar
```

也可使用 `entrust-provider/src/bin/start.sh`（部署目录约定为 `/usr/local/apps/entrust-provider`，需自行写入 `APOLLO_META` 等 JVM 参数）。IDE 直接运行主类 `EntrustApp`。

### 3. Docker

```bash
cd coinex-entrust/docker
cp .env.example .env   # 填写 APOLLO_META、APP_ENV
docker compose up -d --build
```

Compose 默认使用 `host` 网络与外部网络 `apollo_default`；服务名 `entrust-provider`，默认 Dubbo 端口 **20895**（可由环境变量覆盖）。

## 启动后检查

| 检查项 | 通过标准 |
| --- | --- |
| 进程 | 应用完成初始化，无 Apollo / DB / Redis 连接错误 |
| 注册 | Dubbo 侧可发现 `entrust` 相关 Provider |
| 业务 | 可提交测试委托并查询状态（需交易对与账户已就绪） |

心跳脚本若探测 `8000` 端口，以当前环境实际监听为准；仓库内该探测可能与现行实现不一致。
