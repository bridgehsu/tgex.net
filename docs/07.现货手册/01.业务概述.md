# 业务概述

现货是交易所中最基础、最常见的交易方式：用户用一种资产买入另一种资产，订单成交后，双方按成交结果完成资产交换。它不涉及借贷和杠杆，也没有到期结算。许多交易所的交易业务都从现货开始，合约和期权则是在此基础上扩展出的其他产品。

下面先介绍现货的基本概念，再跟随一笔买单，了解资金如何冻结、订单状态如何变化，以及这些变化会如何呈现在交易页面上。


## 现货是什么 {#basics}

说白了：现货就是用一种币换另一种币，换成了就是你的。大家常听到的 BTC，可以理解成要买卖的「货」；USDT 是常见的稳定币，更像「付钱用的币」。在 **BTC/USDT** 这个交易对里：

- 你要买 BTC：付 USDT，拿到 BTC  
- 你要卖 BTC：交出 BTC，拿到 USDT  

一买一卖配对成功，就叫**成交**；两边账户里的币会按成交结果改掉。下单时系统会先把要用的币**冻住**，避免同一笔钱花两次；成交或撤单后再把账算清楚。

它和另外两类产品不一样：

- **合约**：更关心你持了多少仓、保证金够不够，不是简单「币换币到手」  
- **期权**：还要看约定条件和到期怎么算结果  
- **现货**：就盯三件事——单有没有、成交了没有、账户里的币怎么变  

所以看现货，先把下面三个东西分开，别混在一块：

| 看什么 | 人话 |
| --- | --- |
| 委托（订单） | 我还想买/卖多少？这单现在什么状态？ |
| 成交 | 到底换成了多少？按什么价格换的？ |
| 账务（余额） | 我还能用多少？冻住了多少？币最终归谁？ |

打开主流交易所的现货交易页，通常会看到这些信息:

| 页面上 | 你在看什么 |
| --- | --- |
| 交易对 | 这一页买卖的是哪两种币，比如 BTC/USDT |
| 盘口 | 市场上大家挂着的买卖价和量（不一定是你的单） |
| 当前委托 | **你自己**还没做完的单 |
| 成交记录 | 已经换成事实的记录：价格、数量、时间 |
| 余额 | 你账户里可用多少、冻住多少 |
| K 线 | 最近一段时间价格大概怎么走 |

记住两个常见容易混的点：

1. **盘口**是市场意愿；**当前委托**才是你的单。  
2. **盘口里的量**还没换完；**成交记录**里的才是已经换成的。

光记名字还不够。下面就在 **BTC/USDT** 上跟一笔买单：看**委托**怎么从下单变成部分成交再撤掉剩余，**成交**发生了哪一截，**账务**里可用 / 冻结怎么变，以及页面上的当前委托、成交记录、盘口大致会怎样。

## 一笔交易案例 {#complete}

接着上面的三个对象来看。后文现货章节也沿用同一组数，避免每页换例子：

> 限价买入 **0.01 BTC**，先成交 **0.006 BTC**，再撤掉剩下的 **0.004 BTC**。

整笔单可以想成这条线（先看结果，系统内部怎么接力，见后面的主流程）：

<Flow :steps='["提交买单","占用资金","进入撮合","部分成交与结算","盘口与成交更新","撤销剩余","释放占用","盘口再更新"]' />

假设你是用户 A，账户里有 **1,000 USDT**，想按 **60,000 USDT** 的限价买 **0.01 BTC**（大约要准备 600 USDT）。市场上卖方暂时只愿意卖给你 **0.006 BTC**，买不完的部分你再撤单。先不算手续费，并假定成交价就等于你的限价。

对照上一节：表里的「订单」列就是**委托**；「新增 BTC / 支出」对应**成交**；「可用 / 冻结」就是**账务**；最后一列是页面上大概会看到的变化。

| 阶段 | A 可用 USDT | A 冻结 USDT | A 新增 BTC | 订单（委托） | 页面上大致怎样 |
| --- | ---: | ---: | ---: | --- | --- |
| 初始 | 1,000 | 0 | 0 | 还没有单 | 余额里能用 1,000 USDT |
| 下单占用 600 | 400 | 600 | 0 | 未成交 | **当前委托**出现这单；**盘口**这档买量增加 |
| 成交 0.006 BTC | 400 | 240 | 0.006 | 部分成交 | **成交记录**多一笔；盘口买量减少；余额里多了 BTC、冻结变少 |
| 撤销剩余 0.004 BTC | 640 | 0 | 0.006 | 已撤销 | 当前委托去掉剩余；盘口再减掉没成交的那截买量 |

读表时可以按上一节的口诀核对：

1. **委托**：有没有单、还剩多少、最后是部分成交后撤掉  
2. **成交**：真正换成的是 0.006 BTC，花掉约 360 USDT；撤单**不会**把这笔成交取消  
3. **账务**：下单先冻 600 → 成交后冻结降到 240 → 撤单后冻结清零，可用回到 640

### 卖单对称理解

同一组数字从卖方看：用户 B 卖出 0.01 BTC，先成交 0.006，再撤剩余 0.004。下单时冻结 0.01 BTC；成交后减少 0.006 BTC 占用并增加 360 USDT；撤单后解冻剩余 0.004 BTC。买卖共用同一笔成交，只是资产方向相反。

### 手续费与优价成交（教学）

| 扩展 | 教学处理 |
| --- | --- |
| 假设 taker 0.1% 从获得币扣除 | 买方净得 BTC 略少于 0.006；账务需单独记费用流水 |
| 成交价优于买入限价 | 实际扣款小于原预占；多占用部分须在结算或撤单路径中释放并可解释 |
