# 业务概述

<div class="doc-lead">现货交易以基础币与计价币的交换为核心。</div>

本手册面向希望理解现货订单、资金占用与成交结算如何串起来的产品与研发读者。它解释业务规则与设计职责，不逐行讲解源码。若还不熟悉委托、冻结与结算等基础概念，可先阅读[公用基础](/pages/0401)与[现货相关](/pages/0402)。

## 现货交易基础 {#basics}

在 BTC/USDT 交易对中，买方支付 USDT 获得 BTC，卖方支付 BTC 获得 USDT。系统需要确保订单符合规则、被占用的资金不能重复使用、成交后双方资产正确变化。

现货不是“订单价格变动后直接计算收益”的游戏，资产交换是它与周期结果类产品的重要区别。合约关注持仓与保证金，期权关注周期与结果判定；现货则始终围绕「订单 → 成交 → 资产交换」闭环展开。

理解现货时，建议把三个对象分开看：

| 对象 | 回答什么问题 |
| --- | --- |
| 委托 | 还想买/卖多少，处于什么状态 |
| 成交 | 实际换了多少、按什么价格 |
| 账务 | 可用、冻结与资产归属如何变化 |

## 交易界面与核心术语 {#interface}

| 界面区域 | 业务含义 |
| --- | --- |
| 交易对 | 说明交换的两种资产 |
| 盘口 | 展示当前买卖挂单的价格和数量 |
| 下单区域 | 表达方向、类型、价格或数量 |
| 当前委托 | 仍有未完成部分的订单 |
| 成交记录 | 实际成交的价格、数量和时间 |
| K 线 | 某一时间区间内行情的聚合 |

盘口反映尚未成交的挂单意图，成交记录反映已经发生的交换事实，两者不能混用。页面上的余额是结果展示，判断一笔交易是否正确，仍要以委托、成交和账务记录为准。
