# 缓存总览

<div class="doc-lead">平台现货热路径的权威可用/冻结与未完结委托，落在撮合进程内存缓存；本分类按缓存拆开说明结构与职责。</div>

工程侧重：`coinex-match` 的 `com.exch.matching.cache` 包。初始化时装入或按需补齐，运行时由下单 / 成交 / 撤单 / 外部事件改写；Redis 缓冲与 MySQL 落库是旁路，不替代本页所述内存权威态。

## 为什么单独成章

下单主流程与撮合主流程会反复提到「撮合侧钱包」「委托热数据」。把缓存模型拆出来，是为了回答：

1. 权威态存在哪张表 / 哪个 Map？
2. 键是什么、值里有哪些字段？
3. 谁写入、谁读取、和账务服务如何分工？
