# 委托查询主流程

<div class="doc-lead">查询补齐下单 / 撤单同步回包之外的状态：用户经网关进委托，按编号或列表条件取当前委托或历史委托。本路径**只读**，不冻结、不解冻、不改订单簿。</div>

本文假定服务已起来；以 **平台撮合** 为主。下单超时后「结果未知」时，应先走本路径确认终态，见[下单主流程](/pages/070502)。

## 1. 用户 / 机器人 → 应用网关

常见入口：

| 场景 | 典型入参 |
| --- | --- |
| 当前委托列表 | 用户、交易对（可选）、分页 |
| 单笔查询 | 委托编号，或客户端订单号 + 用户 |
| 历史委托 / 成交明细 | 时间窗、交易对、分页 |

## 2. 应用网关 → 委托系统

网关转发；鉴权与限流不在本文展开。委托侧区分「还在热路径上的未完结单」与「已落冷的历史」。

## 3. 委托 → 撮合 / 存储：取数

| 查什么 | 优先读哪里 | 说明 |
| --- | --- | --- |
| 未完结委托（当前委托） | 撮合[委托热数据缓存](/pages/070803) | 与盘口、冻结占用一致的权威热态 |
| 已完结委托 / 成交明细 | 冷库或检索（MySQL / ES 等） | 依赖异步落库；刚成交可能有短暂延迟 |
| 可用 / 冻结余额展示 | 撮合账户热缓存或账务查询接口 | 交易页「还能用多少」以热路径协同后的结果为准，见[用户币币账户缓存](/pages/070802) |

查单失败或暂无记录时：

| 情况 | 建议理解 |
| --- | --- |
| 刚下单成功但列表暂无 | 热写与查询副本之间可能有极短窗口；按委托编号重试，勿再发一笔新单 |
| 超时后既无成功也无失败 | 以查询到的状态为准；禁止在未知时重复下单制造双冻 |
| 历史查不到刚撤的单 | 落库旁路未刷完；热路径若已撤销，以热态或稍后重查为准 |

## 4. 同步返回调用方

查询成功返回委托字段（状态、剩余量、成交量等）或列表。本路径**不**触发深度推送，也**不**改资金。
