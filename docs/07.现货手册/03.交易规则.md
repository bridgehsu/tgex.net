# 交易规则

<div class="doc-lead">先确定订单是否合法，再判断能否成交。合法规则是委托校验的输入；对象怎么建模见[核心设计](/pages/0704)；系统谁执行校验见[系统架构](/pages/0702)。</div>

规则检查发生在资金占用与进入订单簿之前。订单不合法应被拒绝，而不是带着错误参数进入可成交状态。交易对启停与产品配置相关流程，可对照[产品管理与审核流程](/pages/1402#products)。平台限价单上这些检查落在[下单主流程 · 委托校验](/pages/070502)。

## 币种与交易对 {#pairs}

每个交易对需要定义基础币、计价币、交易状态与商户范围。只允许充值的币种不一定已开放交易，存在交易对记录也不代表处于可交易状态。

理解配置时，至少区分三类状态：

| 状态语义 | 含义 |
| --- | --- |
| 币种可充提 | 资产能进出钱包，不代表可以交易 |
| 交易对存在 | 产品定义已建立，不代表当前可下单 |
| 交易对可交易 | 允许按规则提交买卖委托 |

商户范围决定「哪个商户下的用户能看到并交易该产品」。同一交易对在不同商户下可能有不同启停策略；文档只说明需要有边界，不虚构具体商户配置。

## 订单类型 {#types}

已检查的枚举包含限价单与市价单。不要默认工程还支持 IOC、FOK、只挂单等类型；若产品文档未写明，就不能当作现货标准能力。

| 类型 | 价格约束 | 未成交剩余 |
| --- | --- | --- |
| 限价买单 | 成交价不高于限价 | 通常留在订单簿等待更好对手 |
| 限价卖单 | 成交价不低于限价 | 通常留在订单簿等待更好对手 |
| 市价单 | 不承诺固定价格，按可成交流动性执行 | 是否允许残留，按产品规则确认 |

限价单用价格保护用户预期；市价单追求尽快成交，代价是成交价不确定。市价买入以金额提交还是以数量提交，应以实际版本规则为准，本文不固化某一种实现。

**本册流程覆盖**：平台撮合 · 限价单。市价单与第三方撮合的逐步时序未单开；读流程时不要默认二者与限价完全同路径。

## 精度、限额与手续费 {#limits}

价格精度、数量精度、最小数量和最小金额是不同约束。金额计算应使用明确的十进制精度与舍入规则，显示位数不能替代结算精度。

下单前至少要能回答：

1. 价格是否落在允许精度？
2. 数量是否满足最小数量？
3. 价格 × 数量是否满足最小金额？
4. 用户可用余额是否覆盖占用（含费用缓冲，若规则要求）？

手续费需要说明四个轴：费率来源、收取币种、收取时机、舍入方式。本文示例使用假设费率，实际费率由交易产品与商户配置决定。

**演算示例（教学假设，非实时费率）：** 若买方以 60,000 USDT 买入 0.006 BTC，成交金额 360 USDT，假设 taker 费率 0.1% 且从获得的基础币扣除，则手续费约为 0.000006 BTC，买方净得约 0.005994 BTC。真实产品可能从计价币扣、从获得币扣，或采用 maker/taker 分档；写规则时必须写清，不能只写「收手续费」。工程计费与暂存见[手续费计费落地](/pages/070512)。
