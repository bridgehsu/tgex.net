# coinex-market 启动流程

<div class="doc-lead">行情服务维护盘口、成交与 K 线等视图，并通过 Netty 对外推送。</div>

工程目录：`coinex-market`。可运行模块为 `market-provider`（另有 `market-api`、`market-core`）。

## 职责边界

| 项 | 说明 |
| --- | --- |
| 业务职责 | 行情聚合、订阅推送；不负责下单与账务记账 |
| 运行形态 | Spring Boot（含 Web）+ Netty WebSocket 服务 |
| 主类 | `MarketApplication`；启动后执行 `StartExecuteUtil` → `MarketServer.start()` |

撮合产生的成交与盘口变化，需要行情侧及时反映；客户端看到的深度 / 最新成交通常来自本服务或其下游。

## 前置依赖

| 依赖 | 说明 |
| --- | --- |
| Apollo | namespace 常见：`application`、`dev1.base-config`、`exbase-dubbo-config`、`exbase-redis-config` |
| Dubbo | compose 默认端口 **20903**；启动时会拉取 coin / partner 等基础数据 |
| Redis | 行情缓存与协作 |
| Netty | WebSocket 端口等在 Apollo 键前缀 `netty.server.*` |

与 match 存在相互调用关系时，以注册发现与实际调用链为准，不必机械规定绝对先后，但 **Apollo、Dubbo、基础 coin/partner 需先可用**。

## 启动步骤

<Flow :steps='["Apollo 与基础服务就绪","mvn package","配置内存与 apollo.meta","启动 market-provider","确认 Dubbo 与 WS"]' />

### 1. 构建

```bash
cd coinex-market
mvn clean package -DskipTests
```

### 2. 本地或脚本启动

```bash
java -Dapollo.meta=<Apollo地址> -Denv=DEV \
  -jar market-provider/target/market-provider.jar
```

`market-provider/src/bin/start.sh` 默认堆参数较大（如 `-Xmx8g -Xms8g`），本地可按机器调整后启动。

### 3. Docker

```bash
cd coinex-market/docker
cp .env.example .env
docker compose up -d --build
```

服务名 `market-provider`，容器名常见为 `coinex-market-provider`。

## 启动后检查

| 检查项 | 通过标准 |
| --- | --- |
| 进程 | 应用完成初始化，Netty 服务已启动 |
| 注册 | Dubbo 可发现行情相关接口 |
| 推送 | 客户端可按 Apollo 中的 `netty.server.port` / path 建立 WebSocket |
| 业务 | 下单或成交后，深度 / 最新成交有对应更新 |

行情语义见[行情与推送](/pages/0706)；撮合启动见[coinex-match 启动流程](/pages/070503)。
