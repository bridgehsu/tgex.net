# coinex-entrust 启动流程

<div class="doc-lead">委托服务没有「按交易对灌订单簿」那种重初始化；启动后的业务准备是：接口可对外、消息可消费、缓存按第一次请求再装。</div>

工程：`coinex-entrust`。委托侧**没有**撮合那种「按交易对灌订单簿」的全量预热。本文说明启动后如何就绪。

## 和撮合初始化的差别

| | 委托 | 撮合 |
| --- | --- | --- |
| 启动时是否按交易对恢复委托 | 否 | 是 |
| 交易对 / 费率何时进本地缓存 | 首次业务调用再装 | 启动时批量装入 |
| 启动后立刻要做的业务准备 | 接口可对外、消息可消费 | 恢复订单簿并开放接单 |

读本篇时不要期待「先 list 全部交易对再灌内存」的步骤——那一步在撮合 / 行情侧更明显。

## 1. 容器起来之后有什么

### 1.1 基础设施

数据源、MyBatis、Redis（Jedis / Redisson）、Elasticsearch、RocketMQ Producer/Consumer、Dubbo 注册与协议端口在 Spring 刷新阶段完成。  
Consumer 侧通常 `check=false`：**不因下游暂时不在线而拒绝启动**。

### 1.2 导出的业务能力（Provider）

启动完成后，本进程对外提供委托相关 Dubbo 接口（如下单 / 撤单门面、统计、机器人刷单、与行情相关的委托查询等）。  
客户端或撮合、账务补偿链路能发现这些接口，是 entrust「业务上线」的第一层含义。

### 1.3 EventBus 注册（`ContextRefreshedEvent`）

注册例如：

| 监听 | 作用 |
| --- | --- |
| 限购变更 | PRE 等活动限购计数 |
| 批量撤单 | 异步批量撤 |
| 账务超时 | 委单账务超时写库 / 补偿相关 |

此时只是**注册**，不会在启动瞬间跑一遍全站委托。

### 1.4 RocketMQ 消费订阅

启动后订阅的主题包括（以代码启用为准）：预撮合处理、历史委托转 ES、账务超时补偿等。  
有积压时会在启动后立刻开始消费；没有预热「先读完所有历史委托再对外」。

部分旧 Listener 逻辑已注释或降级，以当前仍带 `@Component` / `@RocketMQMessageListener` 的为准。

### 1.5 心跳

`HeartbeatService` 在端口上监听探活；探测时执行类似「查一条委托」的轻量 SQL，确认库连通。  
心跳通过只说明进程 + 数据库探针 OK，不保证撮合各交易对已开放接单。

### 1.6 ApplicationRunner

`EntrustApp` 实现了 `ApplicationRunner`，但业务体为空。Ready 后没有「只跑一次」的全量 init。

### 1.7 启动后约 1 秒的定时任务

`MqService` 开始扫描失败 MQ 重试队列，属于运维向补偿，不是交易对预热。

## 2. 业务数据何时加载

下列本地缓存均为 **LoadingCache / 按需 Redis**，启动时不 bulk load：

| 缓存 | 典型内容 | 触发时机 |
| --- | --- | --- |
| 商户交易对 | partner + trade | 首次下单 / 查对 |
| 币种 | coinId | 首次用到该币 |
| 用户费率 / VIP | 用户维度 | 首次算费 |
| 商户信息 | partnerId | 首次按商户处理 |
| 限购活动 | tradeId | 首次触及 PRE 限购 |
| 委单 JSON | entrustId | 读写单笔委托 |

因此：**第一次真实下单**才会去 Dubbo 拉交易对规则、用户状态等；启动日志里看不到「初始化交易对 success」一类撮合式输出是正常的。

## 3. 就绪含义

| 层级 | 含义 |
| --- | --- |
| 框架 Ready | Spring 完成，进程保活 |
| 接口 Ready | Dubbo 委托 API 已注册 |
| 消息 Ready | 相关 Consumer 已订阅 |
| 探活 Ready | 心跳查库成功 |
| 业务热路径 Ready | 不在启动完成时保证；取决于首次请求时下游 account / match / coin 是否可用 |

下单主路径（V1）会调账务占用、撮合执行等；那些依赖在**请求时**校验，而不是在 entrust 启动时预检全部 Provider。

## 4. 和交易闭环的关系

贯穿示例里「提交买单 / 撤单」请求首先打到委托服务：校验规则、驱动账务冻结、再进入撮合。  
委托服务启动只保证「门面在」；「盘口里已有历史挂单」是撮合初始化恢复出来的，见[撮合初始化链路](/pages/070503)。  
账务占用依赖[账务初始化链路](/pages/070504)；业务语义见[业务流程](/pages/070501)。
