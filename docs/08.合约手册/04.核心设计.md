# 核心设计

<div class="doc-lead">把委托、持仓、保证金账户和风险状态分开建模。合法边界见[交易规则](/pages/0803)；谁持运行态见[系统架构](/pages/0802)；统一案例见[业务概述](/pages/0801)。</div>

## 账户与持仓 {#position}

订单表达待执行意图；持仓表达已成交敞口。撤销未成交的开仓单，**不会**平掉已经建立的持仓。

持仓通常至少包含：

| 字段语义 | 含义 |
| --- | --- |
| 方向 | 多 / 空 |
| 数量 | 当前持仓量 |
| 开仓均价 | 成本均价口径 |
| 可平数量 | 尚允许平仓的数量 |
| 保证金占用 | 该仓（或共享模式下的相关）占用 |

合约账户（热路径）与现货币币账户分离：划转进合约账户后，才参与开仓占用。权威热态见[用户合约账户缓存](/pages/080802)。

## 订单与持仓状态 {#orders}

| 对象 | 状态在说什么 |
| --- | --- |
| 委托 | 受理、部分成交、完全成交、已撤销等 |
| 持仓 | 是否仍有有效敞口；强平过程中可能有锁定 / 清理态 |

二者不能共用一套状态含义。强平需能关联到具体持仓与清算明细，而不是只改一个模糊的「账户状态」。

阅读数量时建议区分：

| 数量概念 | 含义 |
| --- | --- |
| 委托原始量 | 用户提交的开 / 平数量 |
| 已成交量 | 累计成交，只增不减 |
| 剩余委托量 | 尚未成交部分 |
| 持仓量 / 可平量 | 敞口与允许平仓上限 |

## 保证金与盈亏 {#pnl}

线性合约教学公式（说明方向，不含乘数与费用）：

| 方向 | 简化浮盈 |
| --- | --- |
| 多仓 | 约 `数量 ×（参考价 − 开仓均价）` |
| 空仓 | 约 `数量 ×（开仓均价 − 参考价）` |

参考价在风控与展示上常取**标记价**（以产品为准）。已实现盈亏在平仓成交时落定。手续费、资金费、合约乘数都会改实际权益；业务概述案例可先忽略费用。

追加 / 减少保证金、调整杠杆会改变风险状态；调整前应检查持仓、未成交委托与维持要求。是否对所有模式开放手动调整，以产品为准。见[保证金与资金协同](/pages/080505)。

## 风险与强平 {#risk}

风险计算需要稳定的价格与资产口径。权益低于对应维持要求时如何处理，由产品规则与风险引擎决定——**不能**把「亏完初始保证金」写成所有产品的唯一强平条件。

设计上把三阶段分开：

1. **触发**：标记价等更新后扫描，命中风险条件  
2. **执行**：限制用户操作、处理冲突委托、提交强平减仓 / 平仓  
3. **确认**：账户与持仓结果落定，留下清算明细  

流程见[强平与清算](/pages/080503)。下列细节不在本文固化：部分强平阈值、风险准备金分摊、穿仓补偿顺序——需对照当前合约版本后再写入业务说明。
