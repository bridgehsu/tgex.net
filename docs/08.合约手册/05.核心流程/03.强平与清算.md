# 强平与清算

<div class="doc-lead">强平不是用户点的平仓按钮，而是风险旁路：行情刷新标记价 → 撮合扫描 → 命中后限制操作并提交系统强平单 → 改持仓与账户 → 留下清算明细。</div>

价格口径见[交易规则 · 价格](/pages/0803#fees)；对象边界见[核心设计 · 风险](/pages/0804#risk)。

## 1. 标记价进入撮合

合约行情维护指数 / 标记等价格，经消息推给撮合。撮合更新本地价格缓存后，对相关用户 / 仓位做风险扫描。

**过期或异常价格不应继续当实时标记价用**；行情侧应对时间戳、跳变与源中断有降级或暂停策略，见[行情推送流程](/pages/080504)。

## 2. 触发条件（语义）

当权益相对维持保证金等要求不再满足时（具体公式与档位以产品为准），进入强平处理。不要写成「只要亏完开仓时那笔初始保证金就一定强平」——维持要求、浮盈浮亏口径、全仓共享都会改触发点。

## 3. 执行阶段

设计抽象（顺序以当前引擎为准）：

<Flow :steps='["命中风险条件","限制相关开平操作","处理冲突中的用户委托","提交强平减仓或平仓","确认持仓与账户结果","记录清算明细"]' />

要点：

1. **与用户平仓分流**：系统单有独立来源标识；结果仍写同一套持仓 / 账户热缓存。  
2. **可能全平或部分减仓**：是否 `全部强平` 还是 `部分强平` 取决于引擎规则，文档不固化阈值。  
3. **触发 ≠ 清算完成**：扫描命中、强平单进簿、成交清算是不同阶段；中间行情与排队仍可能变化。

## 4. 清算结果

成功后：持仓减少或清零，保证金与盈亏按清算规则落定，必要时涉及风险准备金等（细节另文）。用户应能凭业务编号追溯强平明细，避免「只看到余额少了」。

重复清算必须防重：同一持仓不能被多扣占用或多记亏损。
