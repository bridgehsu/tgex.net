# 保证金与资金协同

<div class="doc-lead">合约开仓占用的是**合约账户**里的保证金，不是现货钱包里的可用余额直接划走。划转与加减保证金必须进入撮合改账通道，才能与持仓占用保持一致。</div>

资金语义总览见[核心资金流程](/pages/0602)；合约热钱包见[用户合约账户缓存](/pages/080802)。

## 为什么要协同

若只改账务库或现货侧余额、不通知合约撮合：

- 用户以为已转入合约，开仓仍报可用不足  
- 或热钱包已加钱、账务未对齐 → 对账困难  

因此划转、充提到合约侧、追加 / 减少保证金，都应变成撮合可串行处理的改账 / 调保证金事件。

## 常见路径

**现货 ↔ 合约划转（语义）**

```
账务 / 划转确认 → 消息 → 合约撮合改合约钱包可用 → 异步流水落库
```

**追加 / 减少保证金**

```
用户申请加 / 减保证金 → 委托或账户门面 → 撮合校验持仓与维持要求 → 改占用与可用
```

减保证金前必须检查：减完后是否仍满足维持要求、是否与未成交开平仓冲突。不满足则拒绝，而不是先减再等强平。

## 和开平仓的关系

| 路径 | 谁改热钱包 / 持仓 | 是否进订单簿 |
| --- | --- | --- |
| 开仓占用 / 平仓释放 | 交易事件 | 是 |
| 划转入金 / 出金 | 改账事件 | 否 |
| 加 / 减保证金 | 调保证金接口 / 事件 | 否 |
| 强平清算 | 强平事件 | 系统单 |

开平仓同步主链**不堵**在「等划转完成」的用户接口上；但没划进合约账户就开不了仓——这是账户余额事实，不是链路设计矛盾。
