# 开仓主流程

<div class="doc-lead">平台永续限价开仓沿时序：用户 / 机器人 → 应用网关 → 合约委托 → 合约撮合；同步返回委托编号（已受理 ≠ 已全部成交）。深度与成交由撮合异步交给行情推送。</div>

本文假定服务已起来、合约产品已可交易；以 **开多 / 开空 · 限价** 为主路径。进簿后的比价与持仓增量在撮合内完成；展示见[行情推送流程](/pages/080504)。统一数字见[业务概述 · 案例](/pages/0801#complete)。

## 1. 用户 / 机器人 → 应用网关

调用方提交开仓：合约产品、开多或开空、价格、数量、杠杆 / 保证金模式、来源等。经应用网关进入合约委托。

## 2. 应用网关 → 合约委托

网关转发与接入；鉴权细节不在本文展开。请求进入委托同步受理段。

## 3. 委托：校验

调撮合「下单」之前，委托侧完成本地 / 配置校验。任一步失败则拒单，**不调撮合、不占用保证金**：

1. 入参完整性（限价须有合法正价格与数量）  
2. 用户可交易状态  
3. 合约产品：存在、启用、涨跌幅、交易时段等  
4. 杠杆与仓位限额（含杠杆档最大可开）  
5. 可用保证金是否可能覆盖占用（预检口径）  
6. 客户端订单号幂等等防重（若启用）

## 4. 委托 → 撮合：开仓

校验通过后，委托同步调用撮合开仓。撮合侧在事件链上：

1. 按规则从合约账户热钱包占用保证金（可用 → 占用）  
2. 建立委托热数据并进入订单簿处理  
3. 若立即与对手成交：增加或加仓持仓、重算均价与占用；剩余量挂簿或结束  

预检够、受理瞬间不够时，以撮合串行结果为准——预检不占最终坑。

## 5. 同步返回调用方

| 结果 | 含义 |
| --- | --- |
| 成功 + 委托编号 | 已受理：保证金按规则占用，委托已进入撮合处理链 |
| 校验 / 预检失败 | 未调撮合或未占用 |
| 撮合拒绝 | 通常无成功占用 |
| 调撮合超时 | **可能已占用**：先查委托 / 持仓终态，禁止未知时再发一笔新开仓 |

持仓明细与全部成交结果不在同步回包里保证带齐；以查询与推送为准。

## 6. 异步旁路：撮合 → 行情

深度 / 成交经消息交给行情，推盘口与成交展示。推送**不改**持仓与保证金权威结果。见[行情推送流程](/pages/080504)。
