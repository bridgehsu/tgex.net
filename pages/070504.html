coinex-account 启动流程 ​

账务在线进程启动后不做全站钱包预热；就绪就是接口与消息通道可用。批处理进程则会在启动后立刻开始扫 pending。

工程：coinex-account。分两个可运行进程理解：

进程角色启动后业务准备
account-provider在线 Dubbo + MQ 改账无全量钱包加载；导出服务、订阅 MQ
account-batch消化 pending、迁 ESApplicationRunner 拉起多组循环任务

本文写的是启动后业务行为，不是运维如何敲启动命令。

先建立正确预期 ​

  • 不会在启动时把所有用户余额装进内存。
  • 不会像撮合那样按交易对恢复订单簿。
  • provider 就绪 = 能响应冻结 / 解冻 / 入账 RPC，并能消费相关 MQ。
  • 端到端账务闭环通常还需要 batch 在跑（pending → 正式流水 / ES）。

account-provider ​

总览 ​

1. 容器与基础设施 ​

Apollo 注入数据源、Dubbo、Redis、ES 等。
MyBatis Mapper、Jedis / Redisson、ES 客户端在刷新阶段建立连接。
Dubbo Consumer check=false 时，下游暂时不在线也不阻断本进程启动。

2. 导出账务能力 ​

扫描并导出大量账务 Dubbo 服务（用户币币钱包、商户钱包、各类业务账户操作、管理向调账等）。
现货下单冻结、成交结算、撤单解冻，最终都依赖这些接口在注册中心可见。

3. EventBus ​

ContextRefreshedEvent 后注册例如：

监听作用
账务异常事件异步写入异常表
资产迁移类事件特定版本资产迁移执行

启动时只注册，不扫全站账户。

4. RocketMQ 消费 ​

启动后订阅多类主题（以代码启用为准），例如：

  • 余额平衡批量更新
  • 币币 / 合约 / 期权等提现或手续费结果
  • OTC 成交入账、取消解冻
  • 外部期货划转 / 订单结果

有积压则启动后立即消费；改账发生在 onMessage，不在启动预热阶段。

5. 心跳 ​

默认探活端口上执行轻量查库（如按固定主键查钱包表），用于确认 DB 可读。
不等于「所有 Dubbo 依赖方已上线」。

6. ApplicationReady 之后 ​

AwaitingNonWebApplicationListener 阻塞保活。
另有按分钟跑的定时任务（如部分充值单对齐、C2C 超时关单），属于运行期调度，不是一次性 init。

7. 运行时才出现的「初始化」 ​

代码里大量 init* 出现在开户 / 首次动某币种钱包等业务方法中，例如用户某业务账户尚不存在时再创建。
那是请求路径上的惰性建账，不要写成「启动时全量 init 钱包」。

本地幂等、流水号占用等依赖 Redis TokenManager，也在请求时使用。

provider 就绪含义 ​

层级含义
框架 Ready进程保活、配置已加载
接口 Ready账务 Dubbo 已注册
消息 Ready资产相关 Consumer 已订阅
探活 Ready心跳查库成功
全量资产视图不存在于启动完成时

account-batch ​

批处理是另一条进程，有明确的启动后业务循环。

ApplicationRunner.run() ​

Spring 就绪后启动多组调度线程（延迟约百毫秒～1 秒后开始），典型包括：

循环业务
批量执行 pending 账务日志消化 pending 类流水
补偿异常 pending 再处理
迁流水到 ESpending / 正式流水检索侧
迁快照到 ES资产快照检索侧

失败时可能降级为更细粒度的单用户执行。
EventBus 上还有批处理异常监听，用于回写 pending 状态。

batch 就绪含义 ​

Runner 已提交任务，且循环已开始扫库。
它不预加载全站余额，但持续让 provider 写下的 pending 被消化。现货成交高峰时，若只起 provider 不起 batch，会出现在线余额已变、检索 / 部分异步链路滞后的现象。

和交易闭环的关系 ​

贯穿示例中的占用、成交扣减冻结、撤单解冻，都由 account-provider 在请求或 MQ 路径上完成。
委托入口见委托初始化链路；撮合见撮合初始化链路；资金动作语义见业务流程。
